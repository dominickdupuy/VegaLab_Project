Test whether an options edge is real before you trade on it.

Vega Lab is a backtesting lab for selling SPX volatility. You plant an edge of known size in a simulated market, run a strategy on it, and check whether a test of that size would have noticed. Then you run the same checks on real SPX data.

The basics

  1. 1

    An option is a bet on how far a price moves

    An option gives the right, not the obligation, to buy (a call) or sell (a put) at a set price, the strike, until a set date. SPX options are on the S&P 500. The seller of a put is paid a premium up front, keeps it if the index stays above the strike, and pays out if it falls below.

  2. 2

    Options are usually priced a little high

    Every option's price implies a volatility, how much the market expects prices to swing. The swings that then happen are usually smaller. That gap is the variance risk premium, measured in vol points. Sellers earn it on average and give much of it back in a crash.

  3. 3

    A simple rule collects it

    The fixed-delta seller sells options a set distance from today's price, out where the index rarely ends up, and rolls them on a schedule. It doesn't learn anything. It is our baseline: the edge a simple rule already gets.

  4. 4

    Can a learning agent do better?

    A reinforcement learning agent learns by trial and error. Each day it sees the market, picks which options to sell (or none), and is rewarded with its profit after costs. Over many simulated episodes it leans toward what paid. Ours uses PPO, a standard algorithm.

  5. 5

    Every answer comes from a backtest

    To judge the rule or the agent, you run it on market data and see what it made. Run the same strategy on different random markets, though, and the results scatter. With an edge this small, luck can look like skill, and skill can look like luck.

Which leads to the problem: how do you tell a real edge from luck? ↓

The problem

The edge an option seller is chasing is small and noisy. A seller's profit from one day to the next swings by far more than the premium itself.

Backtests make it worse. A few lucky runs, costs left out, or a bug that lets the strategy see tomorrow's prices can each turn noise into an apparent profit. So when a backtest, or a reinforcement learning agent, reports that it made money, that alone says little.

What is missing is a number most studies never state: how small an edge could this setup reliably detect? And does a learning agent find a real edge as well as a simple rule does?

Our solution

The deliverable is not a profitable agent. It is a calibrated instrument and a stated detection floor, built in four steps, each a page in the app.

  1. 1

    Plant an edge of known size

    A leak-tested simulator of the SPX options market where we set the premium ourselves, from zero up. The right answer is known before any test runs.

    Synth data →Leak detector →
  2. 2

    Run both strategies on the same markets

    The fixed-delta seller and the PPO agent trade identical market paths, with costs, across many seeds. Pairing them cancels the luck of the draw.

  3. 3

    Find each strategy's detection floor

    A test fixed before the data, run over a sweep of planted premiums, gives the smallest edge each strategy is caught earning 80% of the time.

    Hold the real market up to it

    We measure the premium real SPX options paid and place it on the same scale, which says whether a study of this size could have seen it.

FAQ

Is this trading advice?
No. It is a research tool. It places no trades and recommends none.
Why simulate instead of using real data?
On real data nobody knows the true edge, so a method that found one cannot be told from a method that fit noise. In the simulator we set the edge, so each method is graded first.
Does it use real market data at all?
Yes. The Real data page reads the SPX options panel when it is built on the server, and the premium it measures is what the study's result is compared against.
What do I need to run it locally?
The project's Python venv and Node. Run make web, then make serve, and open port 8600. The simulator needs no market data.
